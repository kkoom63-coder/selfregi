# 배포 전 QA 체크리스트 (필수)

## 구조

- [ ] **중복 id 0건.** `getElementById`는 첫 요소를 잡아 렌더가 통째로 어긋난다. 섹션은 `-sec` 접미사로 분리.
- [ ] 각 `<script>` 블록을 개별 추출해 `node --check`. 멀티 스크립트 파일은 전부 검사.
- [ ] `<div>` 여닫힘 균형 카운트.

## 레이아웃

- [ ] **그리드는 기본 `auto-fit`.** `auto-fill`은 아이템 수 < 컬럼 수일 때 우측에 빈 유령 트랙이 생겨 "왼쪽 쏠림"으로 보인다. 카드 개수가 고정·소수(2~4장)면 `auto-fit`, 런타임에 늘어나는 목록만 `auto-fill` 허용.
- [ ] **1920px 이상(가급적 2560px) 광폭 실측.** 쏠림은 광폭에서만 드러나고 1440px 이하에선 안 잡힌다.
- [ ] 폭 변경 시 모든 섹션 컨테이너 `margin:0 auto`.
- [ ] 혼합 max-width 캡으로 인한 불균등 마진 확인.
- [ ] grid/flex 안 `<button>`은 `width:100%` 명시.
- [ ] 고정 하단바 `env(safe-area-inset-bottom)`.

## 자산·접근성

- [ ] 이미지 404 스캔 (SVG·PNG 자산 repo 업로드 누락 확인).
- [ ] WCAG 대비비 — 특히 소형 회색 텍스트.
- [ ] JSON-LD 유효성.

## Word 템플릿

- [ ] 플레이스홀더 치환 검증은 **`<w:t>` run 단위**로 확인. 전체 텍스트를 join한 뒤 검사하면 run-split 버그를 못 잡는다.
- [ ] 한·영 혼합 입력 시 `w:hint="eastAsia"`가 자동 삽입되어 플레이스홀더가 쪼개진다. 템플릿 수정 시마다 run-split 검사.
- [ ] 플레이스홀더 재수정 시 **텍스트 자체를 건드리지 않는다.** 재입력하면 run-split이 재발한다.

## 진행률 로직

- [ ] 진행률·완료 판정은 '도달'이 아닌 **'실제 열람 집합'(seen 배열)** 기준.

## 패치 안전장치

- `str_replace` 대형 패치 전 `grep -n`으로 타겟 고유성 확인. 공백 차이로 인한 silent no-op 방지.
- 다중 매칭 가능 패턴은 Python count-assert 가드를 건다.
- 작업 전 GitHub HEAD와 로컬 작업본의 차이를 확인한다. 배포본과 다를 수 있다.

## "왼쪽으로 쏠린다" 피드백 대응

스킬 탓·미리보기 비율 탓으로 답하지 않는다. 위 항목 중 원인을 **CSS에서 특정해 명시**할 것.
