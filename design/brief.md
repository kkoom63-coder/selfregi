# 셀프등기24 — 랜딩 리디자인 브리프 (brief.md)

> 이 문서는 index.html 리디자인 시안 생성의 **단일 기준**이다.
> Claude Code 시안 생성 루프(`/design-round`)는 매 라운드 이 문서 + `references/` 이미지 + 직전 `verdict.md`만을 입력으로 삼는다.
> 이 문서와 충돌하는 트렌드·취향 판단은 모두 이 문서가 이긴다.

---

## 1. 제품 한 줄 정의

매매계약에 따른 소유권이전등기를 **법무사 없이 직접** 하도록,
서류 자동생성 + 전 과정 로드맵(동선·번호·케이스 통합)을 제공하는 웹서비스.

- 핵심 해자: 양식 제공이 아니라 **"양식까지 가는 길 전체의 인지부하 제거"**
- 벤치마크: 삼쩜삼(일회성 + 바이럴). 구독 아님.
- 랜딩 유형: **제품 시연형 신뢰 랜딩** (트렌드 시네마틱 ❌, 토스식 차분한 명료함 ⭕)

## 2. 타깃 심리

30~60대, 부동산 매수(대부분 생애 첫/드문 고액 거래), 셀프등기를 검색해서 들어옴.
지배 감정 = **불안**: "내가 해도 되나? 틀리면 어떡하지? 이 사이트 믿어도 되나?"
랜딩의 단일 임무: **불안 → 확신** 전환 후 서류만들기/진단 진입.
화려함은 불안을 키운다. 차분한 근거가 불안을 줄인다.

## 3. 콘텐츠 흐름 (섹션 순서 — 고정)

레퍼런스 3종(Ally / kaiko / Cantor8) 공통 뼈대에 제품 시연 요소를 삽입한 구조.
섹션 순서는 라운드 간 변경 금지. 각 섹션의 **표현 방식**만 변주한다(§8).

### S0. 헤더 / 네비게이션
- 로고(좌) + 메뉴: 서류만들기 · 취득세 계산기 · 로드맵 · Q&A
- 우측 상단 CTA 버튼 1개: "서류 만들기" (스크롤 시 스티키)
- 모바일: 햄버거 대신 하단 스티키 CTA 고려 가능

### S1. 히어로 — 후킹
- H1: **"법무사 수수료 약 120만원, 직접 하면 아낄 수 있습니다"**
  - 반드시 근거 각주: "서울 중위가격 아파트 15억 원 기준" (미세 텍스트)
- 서브: 슬로건 "어려워서 못하는 게 아닙니다. 제대로 된 순서를 몰랐을 뿐입니다."
- CTA 1개: 서류만들기 진입 (보조 링크: 취득세 계산기)
- 히어로에 **진단 진입 요소** 포함: 3문항 미니 진단 위젯 또는 "내 케이스 30초 진단" 버튼
  (질문 예: 어떤 거래인가요? / 아파트·오피스텔? / 대출 있나요? → 결과: 가능 여부 + 예상 절약액 + 경로 미리보기)

### S2. 왜 셀프등기인가 — 매니페스토 (kaiko 스타일 서사)
- 3문장 구조:
  1. 소유권이전등기는 본인이 직접 신청할 수 있는 절차다 (부동산등기법 제24조 — 근거 제시하되 단정 금지)
  2. 부동산 가격이 오르며 법무사 보수도 함께 올랐다
  3. 셀프등기24는 서류가 아니라 **순서와 길 전체**를 안내한다
- 톤: 큰 타이포 선언문 1개 + 짧은 본문. 과장 없음.

### S3. 근거 데이터 — 셀프등기 증가 추세 (Ally 스타일 거대 숫자)
- 셀프(당사자) 등기 접수 건수 추이: 5,654 → 6,851 → 10,361
- 표현: 차트보다 **타이포그래피 숫자** 우선. 그래프 사용 시 "재현 그래프" 라벨 + 출처(등기정보광장) 명기
- 이 섹션 데이터는 추후 주간 자동화 파이프라인(등기정보광장)으로 갱신되는 슬롯

### S4. 제품 시연 — 길 전체 미리보기 ★ 핵심 차별 섹션
- 로드맵의 실제 구조를 보여준다: 온라인 트랙 흐름(위택스 → 은행앱 → 전자수입인지 → 인터넷등기소 → **등기소는 한 번만**)
- 3~4단계는 선명하게, 세부 단계는 블러/잠금 처리 (roadmap_preview 훅)
- 목적: "이 서비스는 문서 파일이 아니라 내 손을 잡고 걷는 길이다"를 시각으로 증명

### S5. 이용 절차 — 4단계 (Ally 넘버링 스타일)
1. 정보 입력 (5분)
2. 위임장 등 서류 즉시 발급
3. 로드맵 따라 납부·발급 진행
4. 등기소 접수 완료
- 실제 순서가 있는 콘텐츠이므로 넘버링 사용이 정당함

### S6. 뉴스룸 (Cantor8 Newsroom 스타일)
- 셀프등기·부동산 뉴스 헤드라인 카드 3~4개 (뉴스1 2025.8, 헤럴드경제 2026.3 등)
- **헤드라인 인용 카드만** — 기사 이미지 캡처 금지(저작권), 출처·날짜 명기
- 추후 뉴스 모니터링 자동화로 갱신되는 슬롯

### S7. 가격 · 정책 — 정직 섹션
- 현재 상태 고지 (무료 베타 → 추후 유료 전환 예정이면 그대로 표기)
- 재발급 정책 요약: 서비스 귀책 무제한 / 사용자 귀책 N회 (환불 아님 — "직접하면 무료" 표현 금지)
- 매도인 개인정보 원칙 한 줄: "매도인 주민등록번호는 수집하지 않습니다" → 신뢰 신호로 활용

### S8. Q&A
- 4~6문항. 불안 직격 질문 우선: "법무사 없이 정말 되나요?" / "은행 대출이 있는데요?" / "실수하면요?"
- 답변 톤: 근거 제시 + "최종 확인은 관할등기소" 유지

### S9. 최종 CTA 블록 (푸터 아님 — 독립 섹션)
- 히어로 후킹의 변주 + CTA 반복. 예: "오늘 발급하고, 이번 주에 접수하세요"
- 레퍼런스 3종 모두 이 블록으로 끝남. 생략 금지.

### S10. 푸터
- 서비스 소개, 사업자 정보(간이과세자), 블로그 링크(티스토리·네이버)
- **개인정보 면책 고지 필수 배치** (프로젝트 규칙)
- 빈 링크(href="#") 금지

## 4. 카피 규칙 (엄수 — audit.js 검사 대상)

- "무조건", "100% 가능", "최대 30만원" 등 단정·과장 금지
- 모든 금액·통계에 근거 각주/출처
- 가짜 후기·가짜 로고·조작된 사회적 증거 금지
- "직접하면 무료" 프레이밍 금지
- 법령은 제시하되 단정하지 않음. "최종 확인은 관할등기소" 톤
- 문장형 헤드라인(구호체 금지), 능동태, 버튼은 동작 그대로("서류 만들기" ⭕ / "시작하기" 지양)

## 5. 디자인 토큰

### 컬러
- `--navy: #1e3a5f` (주 텍스트/딥 배경)
- `--blue: #2a5f9e` (인터랙션/링크)
- `--gold: #b8952e` (악센트 — **한 화면에 한 곳만**)
- 배경: 화이트 기본. 다크 섹션은 S4 또는 S5 중 **최대 1개**만 허용 (Ally의 다크 프로세스 블록 문법)
- 금지: 시네마틱 다크 전면, 그래디언트 남용, 크림+테라코타 AI 기본값

### 타이포그래피 — 레퍼런스 3종 공통 특징의 한국어 이식 (강제)
폰트: **Pretendard Variable 단일 패밀리** (Noto Sans KR 기본값 금지)

1. **웨이트 이원화**: 디스플레이 800~900(ExtraBold~Black) / 본문 400(Regular). **500~600 중간 웨이트 사용 금지** — 균일한 Medium이 "AI틱함"의 주범
2. **극단적 크기 점프**: 히어로 H1 모바일 2.6~3.2rem · PC 4.5~7rem / 본문 1rem. 완만한 스케일(2→1.5→1.25) 금지
3. **디스플레이 자간·행간 타이트**: letter-spacing -0.02~-0.04em, line-height 1.05~1.15 (한글 기준)
4. **문장형 헤드라인 + 마침표**: "약 120만원, 아낄 수 있습니다." — 구호체 금지
5. **악센트는 헤드라인당 1곳**: gold 밑줄 또는 색상, 둘 다 금지
6. **통계 = 타이포**: 거대 숫자(5rem+) + 작은 단위 + 미세 출처(0.75rem). 파이차트·게이지 금지
7. **eyebrow 라벨**: 섹션 상단 소형 라벨(0.8rem, letter-spacing +0.08em, navy 60% 투명도)
8. **본문 컬럼 폭 제한**: 한 줄 32~42자(한글). 풀폭 본문 금지

### 안티패턴 (발견 즉시 kill)
- everything-is-a-card: 모든 섹션이 동일한 카드 그리드
- 동일한 섹션 해부: 제목+부제+3열 카드 반복
- 균일 타이포 웨이트, 소심한 컬러 분포 (gold가 아무 데도/모든 데 있음)
- 제품 아티팩트 부재: 실제 화면·서류·로드맵이 안 보이는 추상 일러스트만 있는 랜딩
- 이모지 사용 (숫자/텍스트 뱃지로 대체 — roadmap.html만 예외)

## 6. 기술 제약

- 단일 HTML 파일, 인라인 CSS/JS. 프레임워크 금지
- 모바일 퍼스트 (사용자 다수 모바일). `user-scalable=no` 금지
- Pretendard: CDN(jsdelivr) 로드
- 시안 단계에서 대형 base64·실데이터 불필요 — 더미 유지
- 접근성 바닥선: 키보드 포커스 가시화, 명도 대비 AA

## 7. 시안 생성 규칙 (라운드당)

- 시안 수: **5개** (variant-a ~ e)
- 각 시안은 §8 변주 축의 **이름 붙은 조합**을 탐색하고, 그 결정을 `notes.md`에 기록
- §3 섹션 순서·§4 카피 규칙·§5 타이포 강제 조항은 모든 시안 공통 (변주 대상 아님)
- 전 시안을 iframe으로 나열한 `gallery.html` 생성 (시안명 + 탐색한 축 표기)

## 8. 변주 축 (시안 간 차이는 반드시 이 축들에서만 발생)

| 축 | 옵션 |
|---|---|

| D. 로드맵 미리보기(S4) 형태 | 수평 타임라인 / 수직 지도형 / 카드 스택+블러 |

## 9. 판정 루프

- 리뷰: `gallery.html` 열람 → `verdict.md`에 시안별 `keep / kill / remix(지시)` 기록
- 다음 라운드: keep 시안을 씨앗으로, remix 지시 반영, kill된 조합은 재등장 금지
- verdict가 없으면 다음 라운드 실행하지 않음 (무한 노이즈 방지)

## 10. 레퍼런스 사용 규칙

- `references/`에는 사용자가 직접 큐레이션한 스크린샷만 넣는다 (자동 수집 금지)
- 레퍼런스는 **패턴·타이포 문법 추출용**. 화면 통째 클론 금지 (저작권)
- 현재 확정 레퍼런스: Ally(신뢰·근거 문법) / kaiko(매니페스토·여백) / Cantor8(뉴스룸·기술 신뢰)
